# MITM прокси сервер

Прокси сервер выступает посредником между клиентом и сервером. Данный прокси умеет обрабатывать запросы и ответы, http и https соединения.
Суть MITM прокси в том, что он умеет читать и расшифровывать HTTPS трафик между браузером и сервером (прокси находится между ними, перехватывая запросы).  

# Что умеет
- Обслуживание нескольких пользователей за раз
- Работа в любом современном браузере(т.к. поддерживает https протокол)
- Ведение логов(в файл и консоль одновременно)
- Генерация ключей и сертификатов: в реальном времени создаются ключи и сертификаты для произведения TLS рукопожатий
- Поддержка HTTP 1.1 / IPv6

# Стек технологий

- Python
- Socket, Threading, Logging, Cryptography, H11, Urllib

# Изменения
- Создана раздельная архитектура проекта
- Исправлены некоторые ошибки утечек сокета remote_socket в функциях http_funf и https_funf (ранее сокет не закрывался если была ошибка NameError при попытке создать remote_socket)
- Добавлены множество конструкций Try/Except/Finally для подробного ведения логов ошибок и дальнейшего их исправления. Теперь программа ведет себя более предсказуемо
- Хост, порт, конфигурации логгера и т.д. вынесены в отдельный файл config.py. Теперь можно настроить прокси под себя
- Все сокеты обернуты в конструкцию with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as... Все утечки сокетов предотвращены, код стал более чистым.
- Внедрение Cryptography и ssl: модуль ssl оборачивает обычные TCP сокеты в TLS для создания зашифрованного туннеля, далее Cryptography занимается созданием сертификатов и их подписыванием через корневой сертификат в Windows (или другой ос)
- Изменена логика работы потоков(используется lock что бы потоки не мешали друг другу) и чтения сертификатов (теперь корневые сертификат и ключ читаются 1 раз, что ускоряет работу прокси. Также теперь сертификаты создаются через временные .tmp файлы, чтобы чужой поток не пытался читать недописанный или пустой файл сертификата).
- Исправлена логика функции http_func (обработчик http трафика). Теперь она работает более стабильно
- Внедрение H11 и Urllib. В отличие от ручного парсинга данные библиотеки обеспечивают более стабильную обработку запросов

# Как запустить
1. Клонируйте репозиторий:
```
git clone https://github.com/macos198766-arch/proxy
```
2. Создайте в корне папки proxy корневой сертификат и ключ:
```
python3 make_ca.py
```
На этом этапе создастся каталог certs/ca, в нем (папка ca) будут лежать 2 файла: rootCA.crt, rootCA.key. 
В Windows:
- Дважды кликните ЛКМ по rootCA.crt
- Далее нажмите: "Установить сертификат" -> "Локальный компьютер" -> "Далее" -> "Поместить все сертификаты в следующее хранилище" -> "Доверенные корневые центры сертификации" -> Ок -> Далее -> Готово

3. Запуск основной функции:

```
python3 proxy_server.py
```
4. Тестирование.

- Либо через curl в bash:

```
curl -v -x http://localhost:8888 http://example.com
curl -v -x http://localhost:8888 https://www.google.com
```
- Либо В Windows -> "Параметры" -> Сеть -> Прокси -> Введите "localhost" в Адрес и в 8888 Порт(опционально, можно изменить в файле config.py)
Далее можно выходить в интернет просто через браузер

# Критические проблемы

- Отсутствие тестов на ос помимо Windows
- Замедление работы. Поскольку python - медленный язык + в данном проекте используется Threading вместо Asyncio, скорость загрузки страниц может заметно проседать
- Отсутствие поддержки HTTP 2 и более новых протоколов из-за чего сервер может принудительно разрывать соединение

# Примечание
- В браузере FireFox иногда приходится загружать корневой сертификат прямо в сами настройки браузера для корректной работы
- Рекомендуется удалять все временные сертификаты и ключи из корня папки certs (папку ca и файлы rootCA удалять нельзя) после окончания работы прокси для сохранения памяти устройства
- Иногда при первом использовании прокси браузер может попросить пройти капчу; некоторые сервера могут блокировать доступ тк считают прокси сервер подозрительной активностью 
- Тестируйте прокси только на своих локальных сетях
- Никому не доверяйте свои корневые сертификаты
